# Contributing

This is an experimental workflow. Useful contributions include reproducible failure reports, clearer documentation and narrowly scoped fixes. You do not need direct write access to report an issue or propose a pull request.

## Report a problem

Open an issue with a small fictional or redacted brief, the expected behavior, the actual output and the model/environment used. Say which checks actually ran. Remove private client material, account data and credentials before posting. Never post a raw private conversation as evidence.

The known acceptance/signature scope failure is a useful starting point. A change should show why it addresses a failure, not merely add another promise to the instructions.

## Propose a change

1. Open an issue to discuss large changes first. Small corrections can go straight to a pull request.
2. Fork the repository and create a branch for one change.
3. Keep workflow changes separate from README and formatting changes.
4. Include a small before/after example with the same brief and settings. State test limits and any checks not run.
5. Open a pull request. The maintainer reviews and decides whether to merge; a submitted PR is not an accepted change.

Use fictional material you have the right to share. Do not upload copied proprietary skills, private project records or third-party material without permission.

## Testing expectations

Preserve source facts; do not add obligations or approval language. Keep unknown prices unresolved rather than inventing them. Check saved artifacts where available, and report missing rendering or independent review as NOT RUN. Do not call a wording change a reliable fix based on one favorable output.
